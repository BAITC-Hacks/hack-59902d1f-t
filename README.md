# Beeline Tariff Marketing Campaign Agent

**Решение на основе Bayesian Contextual Bandit + Integer Portfolio Optimizer**

---

## Обзор подхода

### Проблема
- **23,441 абонент**, нужно решить кому предложить смену тарифа
- **Бюджет ограничен**: 100,000 у.е., максимум 15,000 контактов
- **Downselling риск**: часть переходов дают минус (клиент платит меньше)
- **Неопределённость**: история на другой выборке, результаты на целевой неизвестны

### Решение

Двухфазный подход:

#### **Фаза 1: Bayesian Contextual Bandit (Разведка)**
1. **Инициализация**: Создаём множество "вооружений" (комбинация сегмент → тариф → канал)
   - Сегменты: ARPU (LOW/MID/HIGH) × Data Usage (NON_USER/LITE/HEAVY) × Call Volume (LOW/MEDIUM/HIGH)
   - Итого: 3×3×3 = 27 базовых сегментов
   - Комбинируем с 21 тарифом и 4 каналами

2. **Thompson Sampling** для разведки:
   - Для каждого "вооружения" ведём Beta-распределение успеха
   - Сэмплируем из posteriori (Thompson sampling)
   - Выбираем топ-15 кандидатов на пилоты
   
3. **Адаптивные пилоты** (10-20% бюджета на разведку):
   - Размер пилота: 20-100 клиентов (адаптивный)
   - Обновляем posterior после каждого пилота
   - Ловим комбинации с положительным ROI

4. **Построение posterior'а**:
   ```
   α_posterior = α_prior + n_trials
   β_posterior = β_prior + (100 - n_trials)
   ```
   → Больше информации из пилотов → меньше неопределённость

#### **Фаза 2: Campaign Construction**
- Берём лучшие пилоты (положительный observed_gain)
- Масштабируем на весь сегмент с консервативным коэффициентом 0.8
- Оцениваем ожидаемый чистый gain (прирост ARPU - стоимость контактов)
- Ограничиваем охват: макс 5,000 клиентов per campaign

#### **Фаза 3: Integer Portfolio Optimization**
- Решаем задачу выбора подмножества кампаний:
  ```
  maximize: Σ(expected_gain_i * x_i)
  subject to:
    Σ(cost_i * x_i) ≤ budget
    Σ(x_i) ≤ 10 campaigns
    x_i ∈ {0, 1}
  ```
- Используем **PuLP** (если доступна) или жадный алгоритм
- Результат: оптимальный набор из ≤10 кампаний

## Ключевые компоненты

### 1. **BayesianContextualBandit**
```python
class BayesianContextualBandit:
    - extract_segments()       # 27 базовых сегментов
    - _initialize_arms()        # Инициируем Beta(1, 1) для каждой комбинации
    - select_arms_thompson()    # Thompson sampling
    - update_arm()              # Обновляем posterior после пилота
```

**Thompson Sampling**: 
- Сэмплируем вероятность успеха из Beta(α, β)
- Балансирует разведку и эксплуатацию автоматически
-높은 неопределённость → высокое сэмплируемое значение → больше шансов выбраться

### 2. **IntegerPortfolioOptimizer**
```python
class IntegerPortfolioOptimizer:
    - optimize()              # Выбор оптимального подмножества
    - _optimize_with_pulp()   # Integer programming (если PuLP доступна)
    - _optimize_greedy()      # Fallback: жадный по ROI
```

**Почему Integer Programming?**
- Нельзя запустить 0.7 кампании
- Нужна точная оптимизация под бюджет
- PuLP решает задачу точно (NP-сложная, но размер мал: ≤100 кампаний)

### 3. **Agent.act(env)**
```
Инициализируем bandit
    ↓
Фаза 1: Разведка (Thompson sampling)
    - Выбираем 15 кандидатов
    - Запускаем пилоты (20-100 клиентов)
    - Обновляем posterior
    ↓
Фаза 2: Построение кампаний
    - Берём лучшие пилоты
    - Масштабируем на полные сегменты
    ↓
Фаза 3: Оптимизация портфеля
    - Integer programming
    - Выбираем оптимальное подмножество
    ↓
Возвращаем ≤10 кампаний
```

## Особенности реализации

### Uncertainty Quantification
- **Beta posterior** для каждого "вооружения"
- Пилот на 100 клиентах точнее, чем на 30
- Консервативная оценка: берём 80% от пилотного результата при масштабировании

### Adaptive Exploration
- Размер пилота: `min(100, max(20, √(n_customers/100)))`
- Выделяем 40% бюджета на разведку
- Макс 15-20 пилотов в зависимости от `pilots_left`

### Channel Selection
- **Push** (бесплатно): для массовых, низкоэффективных кампаний
- **SMS** (4 у.е.): средневесовые сегменты
- **Digital ads** (22 у.е.): таргетированные
- **Call** (160 у.е.): VIP сегменты (HIGH ARPU)

Автоматически выбирается из пилотов с лучшим ROI

### Robustness
- Try/except вокруг пилотов → если пилот упадёт, продолжаем работу
- Fallback от PuLP к жадному алгоритму
- Консервативные оценки (0.8 коэффициент) → не переоцениваем

## Ожидаемые результаты

### На мок-данных (local_eval)
- **Пилотов проведено**: 10-20 (разведка лучших сегментов)
- **Кампаний выбрано**: 5-10 (из-за целочисленного ограничения)
- **Expected gain**: +15-30% от baseline (150 млн)
- **Стабильность**: низкая дисперсия при повторных запусках (--runs 10)

### Почему работает
1. **Thompson sampling** → научное управление разведкой
2. **Posterior обновления** → учим что-то новое из каждого пилота
3. **Integer optimization** → выбираем truly best subset
4. **Uncertainty** → не переоцениваем пилоты (коэф 0.8)
